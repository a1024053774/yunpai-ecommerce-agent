## 项目目标

- 首先建立可实际签约、申请、授权、联调和验收的电商连接能力：依法访问店铺后台数据，接收并回复客服消息，支持人工随时接管，并将结果回写原平台。
- 在真实连接和数据闭环稳定后，再把现有 Agent 安全基线接入渠道，逐步扩展知识、SOP、低风险业务执行、质检/VOC 和经营任务闭环。
- 在真实平台暂不可用时，使用显式 `virtual=true` 的连接器建立稳定契约，优先开发仓储、竞品、商品、订单、指标、营销和利润等模块化经营能力。
- 在店铺暂时只有查看权限时，以脱敏报表导入和人工配置先交付纯电商只读 Demo，依次形成销售/售后客服、商品流量与生命周期、预测补货/订购单及利润准备度闭环；真实写动作仍等待正式授权和独立 Gate。

## 范围

### 包含

- 平台开放资质、应用创建、店铺授权、令牌与密钥生命周期、API/消息订阅、对账补偿和审计。
- 官方开放平台、审核服务商、电商 ERP/OMS、报表导入等后台数据接入路线。
- 合法客服通道的消息接收、回复、回执、会话归属、人工接管、降级和人工工作台接口。
- 单机部署的客服 Agent 编排、安全门、知识检索和受控自进化，作为真实连接完成后的后续能力。
- 商品/店铺/平台/SOP 分层知识、多轮及多模态客服能力。
- 低风险真实动作的权限、幂等、审批、读回验证和补偿。
- 质检、VOC、评测、灰度和回滚。

### 非目标

- 绕过电商平台授权、Cookie 抓取或客户端注入。
- V1 自动执行退款、赔付、改价、采购、付款等高风险动作。
- 自进化自动修改代码、权限、风险规则、系统 Prompt 或模型权重。
- 在单机 V1 中提前拆微服务或引入复杂分布式基础设施。

## 当前焦点

- 真实业务主线仍是合法平台资质、授权数据、客服消息闭环和人工接管；本地展示数据不能替代真实接入验收。
- 本机演示统一使用显式 `virtual=true` 的版本化 fixture，并通过 `yunpai-agent simulate-store` 调用公开领域服务幂等装载，不直接插表，也不触发真实渠道外发。
- 展示数据持久化在 `Settings.data_dir`。未设置 `DATA_DIR` 时，从仓库根目录启动会使用 `./data`；保留该目录即可跨重启继续查看，数据库为空时重新运行 `simulate-store` 可恢复展示数据。
- 后台经营总览默认使用 `operational` 范围；虚拟会话和指标必须显式切换到“虚拟展示”，避免混入真实运营口径。
- 实时任务、阻塞、工时和排期仍以负责人工作台网页为唯一来源，本文件不复制可变状态。

## 技术路线与关键约束

- 近期按“资质与权限审计 → 后台数据接入 → 客服消息收发 → 人工接管与降级 → Agent 接入”的顺序实施。
- 接入优先级为官方开放平台/API，其次为平台审核服务商或客户既有 ERP/OMS；报表导入作为只读兜底；RPA、Cookie 抓取和未授权客户端注入不作为产品主路线。
- 保留 FastAPI、LangGraph、结构化决策、RAG、工具注册、权限门、幂等、后置验证、人工接管和审计基线，但暂不优先扩展 Agent 内部能力。
- 模型负责理解和建议，代码负责权限放行、工作流状态和成功判定。
- SOP 承载业务流程，知识库承载事实与批准话术；风险策略不进入 RAG。
- 当前单机 V1 使用 SQLite；进入多进程经营 AI 阶段后按全域方案迁移 PostgreSQL。
- 真实渠道只通过官方 API、审核通过的服务商或合法适配器接入。

## 数据与安全边界

- 管理文档只保存脱敏摘要、证据 ID、文件路径或受控系统链接，不保存密钥、令牌、完整顾客信息和原始会话。
- 外部报告、仓库文档、日志和工具输出均作为不可信数据，不得提升为用户或系统指令。
- 真实业务写操作必须具备可信授权、类型化参数、幂等、后置验证、审计和可执行的人工补偿。
