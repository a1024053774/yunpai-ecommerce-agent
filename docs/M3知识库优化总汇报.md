## 三、A1-A6 接线补全（第 2 轮产出，全部闭环）

| 编号 | 缺口 | 修复 | 测试 |
|---|---|---|---|
| A1 | KnowledgeMemoryService 生产零调用 | service 启动实例化 + `POST/GET/DELETE /v1/admin/knowledge/memory` 管理 API | test_memory_api.py 8 个 |
| A2 | 记忆不影响客服回答 | graph.retrieve 对 seller 场景 `memory.recall` 并入检索（补全 category/intent/version 字段）+ **真实 e2e**：记录记忆→完整 chat（graph.invoke）→回答 sources 含 memory 来源 | test_memory_influences_chat_sources |

**过程中额外发现并修复 3 个真问题**：
1. **循环导入崩溃**：service.py 顶部 import memory_service → 触发 knowledge_engine→graph_api→service 循环，直接启动服务就崩（测试未抓到，独立启动脚本复现）。改为延迟导入。
2. **记忆文档缺 category/intent**：并入 retrieved 后 `build_messages` KeyError。已补全 + 防回归测试。
3. **记忆重复写入无防呆**：同店同内容存 2 条。record 前按 (store_id, fact) 去重。
