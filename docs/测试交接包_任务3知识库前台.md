## 二、环境准备（约 30 分钟）

### 1. Python 环境（项目已有）

```bash
python3.11 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
python -m pip install -e ".[dev]"
```

### 2. 启动服务（关键！需先加载 .env）

项目**不会自动读取 .env**，启动前必须先加载：

```bash
# Windows Git Bash
cd d:/yunpai-ecommerce-agent-main
export $(grep -v '^#' .env | grep -v '^$' | xargs)
.venv/Scripts/python.exe -c "
from ecommerce_agent.api import create_app
import uvicorn
uvicorn.run(create_app(), host='127.0.0.1', port=8000, log_level='warning')"
```

> **首次需生成 .env**（从 `.env.example` 复制，把 3 个密钥替换掉）：
> `ADMIN_API_KEY`、`BOOTSTRAP_CLIENT_KEY`、`SUBJECT_HASH_KEY`。
> 本地开发建议 `MODEL_MOCK_MODE=true`（不依赖外部模型）。

### 3. Neo4j（需启动，供搜索/图谱用）

```bash
# 本机已装：D:\neo4j-community-2026.04.0
D:\neo4j-community-2026.04.0\bin\neo4j.bat console
# 账号：neo4j / ${NEO4J_PASSWORD:-change-me}
```

- 地址：http://127.0.0.1:8000/admin
- 左侧导航 → **「知识库」**（第 17 个模块，紧挨"知识与 SOP"）

## 四、测试人需要知道的

### 1. 数据分层（关键认知）

| 层 | 内容 | 可编辑 |
|---|---|---|
| **资产层**（`knowledge_graph_output/02_clean/`） | 六类实体 JSON（商品/SKU/品类/属性/政策/话术/FAQ/规则） | **严格只读**，改代码不碰它 |
| **运行时表**（knowledge） | 导入的 Q&A 知识（id 带 `kg-` 前缀） | **可编辑**，走 `/v1/admin/knowledge` |
| **Neo4j 图谱** | 导入的实体+关系 | 数据重建需重跑 Cypher |

**Wiki 显示** = 运行时表（Q&A 为准）+ 资产层（实体类 + 属性补充），**编辑即时生效**。

### 2. 图谱滞后（设计边界）

- `/v1/graph/search` 和 `knowledge_graph.html` 读的是 **Neo4j/导出快照**
- 编辑运行时表**不会自动同步**到图谱——搜索可能返回旧知识
- 图谱宿主页会显示"上次导出时间 vs 知识更新时间"，不一致时提示重跑导出
- 重跑：`.venv/Scripts/python.exe -m ecommerce_agent.knowledge_engine.export_graph`

### 3. 已知边界

- 实体类（商品/SKU/品类/属性）**不可编辑**，只读展示
- 编辑只覆盖 Q&A 类，且行必须带 tenant_id
- 图谱可视化是**静态快照**，不自动刷新
- 知识进化来源（`evolution:`）的行 layer=industry，Wiki 标注来源不强行归层
- 登录凭证存 sessionStorage（本地一体机低风险，沿现状）

### 4. 服务占用

- 启动服务前**确认 8000 端口空闲**（`netstat -ano | grep :8000`），否则报 data directory in use
- 旧服务未停止时启动会报 `DisasterRecoveryError`
