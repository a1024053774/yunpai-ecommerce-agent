# 需求预测业务展示设计

## 目标

让经营人员能直接理解预测依据和结果，而不必阅读运行编号、数据水位或模型误差等诊断字段。

## 展示范围

需求预测区只保留店铺和商品 SKU 两个查询条件。查询到已保存的预测运行后，页面按以下顺序展示：

1. **时序预测方法**：预测方法名称、预测窗口、选择结论和需求类型。
2. **预测摘要**：`基于 N 天历史销售数据，预测未来 H 天需求`。其中 `N` 是可用日需求事实数，`H` 是本次预测窗口。
3. **已观测需求与历史预测对比**：用于判断该方法在已发生销售中的误差。
4. **未来每日需求预测**：逐日显示三个需求把握水平。

不在预测主界面展示运行编号、训练截止时间、来源水位、原始 WAPE、多模型对比、库存快照、库存风险或补货计划。这些内容属于技术诊断或后续库存业务，不影响理解日需求预测。

## 预测区间的业务口径

未来每日需求预测使用三个由低到高的需求区间：

| 页面名称 | 接口字段 | 业务含义 |
| --- | --- | --- |
| 50% 把握需求 | `p50` | 中性预测，约有一半概率实际需求不高于该值。 |
| 80% 把握需求 | `p80` | 较稳妥的需求量，通常适合作为默认备货依据。 |
| 95% 把握需求 | `p95` | 高保障需求量，适用于缺货损失明显高于库存占用的商品。 |

页面可在列名中保留 `P50`、`P80`、`P95` 作为简写，但必须显示对应的中文业务含义。

## 计量单位与补货换算

预测引擎以十进制数计算日需求，避免在聚合和预测过程中丢失重量、体积等小数单位。接入商品主数据后，展示和补货换算遵守以下规则：

- 按件、盒、台等离散商品：展示和建议采购数量向上取整到最小单位。
- 按斤、千克、升、米等连续商品：按 SKU 的最小销售单位保留适当小数位。
- 有最小采购量或包装规格的商品：先计算预测需求，再按最小采购量和采购倍数向上换算为可采购数量。

SKU 主数据需提供计量单位、最小销售或采购单位，以及采购倍数或包装规格。预测模型只给出需求量；计量展示和采购取整由接入层处理。

## 非目标

- 不改变预测算法、模型选择、历史回测或预测持久化。
- 不创建真实采购订单，也不更新库存。
- 不在本次展示调整中新增 SKU 计量字段；该字段由后续商品主数据接入时提供。

## 验收

- 查询到预测时，主界面显示“基于 N 天历史销售数据，预测未来 H 天需求”。
- 主界面不再存在独立的“最新预测”方框，且不显示运行编号、数据水位或 WAPE。
- 三个未来需求列有中文业务含义，并仍与 `p50`、`p80`、`p95` 一一对应。
- 文档明确离散和连续计量单位的展示、采购取整边界。
