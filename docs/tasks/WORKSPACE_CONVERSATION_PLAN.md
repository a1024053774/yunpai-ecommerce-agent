# 统筹 Agent 会话持久化实施计划

## 目标与约束

在 PR #9 统筹工作台上交付单负责人私有多会话：刷新和重启可恢复、处理过程可回看、会话上下文隔离。遵循 TDD，不复用顾客客服会话表，不新增依赖，不自行占用 Schema 29/30。

## 任务 1：冻结 API 契约

- 在 `tests/test_workspace_conversations.py` 先写认证、创建、列表、归属隔离、消息恢复和归档的失败测试。
- 运行测试，确认因路由不存在而失败。
- 在 `workspace_api.py` 定义请求/响应模型和路由骨架。

## 任务 2：Schema 迁移与仓储

- 等负责人分配新 Schema 版本号。
- 在 `database.py` 新增两张独立表、归属索引和消息时间索引。
- 覆盖前一版本升级、重复初始化、表约束和遗留 `generating` 收敛测试。
- 实现创建、列表、读取、改名、归档、开始消息和完成消息的原子仓储方法。

## 任务 3：流式聊天持久化

- 路径会话 ID 代替前端随机 ID。
- 服务端读取最近 12 条已完成消息并构造 `WorkspaceChatRequest.history`。
- 在开始、成功、错误和客户端中断路径更新消息状态。
- 保存工具摘要、确认卡片和 trace ID。

## 任务 4：工作台多会话界面

- 增加左侧最近会话列表、新建、重命名和归档控件。
- 使用 `localStorage` 仅保存最后打开的会话 ID，不保存聊天正文或凭据。
- 页面加载时从后端回读会话和消息并恢复处理过程。
- 增加空状态、加载状态、未完成状态和错误提示。

## 任务 5：验收与交付

- 定向运行会话、统筹 Agent、鉴权和迁移测试。
- 浏览器实际验证一轮刷新、三轮刷新、会话切换、归档和中断恢复。
- 验证控制台无错误，桌面和移动视口无重叠。
- 执行 `compileall`、`git diff --check` 和 project-to-act 校验。
- 全部能力验证后再记录 project-to-act 证据；未获 Schema 号或未完成迁移时不得声称完成。
