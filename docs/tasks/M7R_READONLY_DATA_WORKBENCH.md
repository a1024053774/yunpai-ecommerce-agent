# M7-R 只读经营数据与 Demo 事实底座 — 任务书

> 代码域：报表导入、来源证据、商品身份映射和数据准备度。
> 项目负责人及里程碑收口人：**闫睿涵**。
> 里程碑开发负责人：**谢良璇**（WP1～WP4）；独立验收负责人：**缪海南**（WP5）。
> 工作包分工以本文为唯一来源；动态状态、工时和日期只在负责人工作台网页维护。
> 上位路线：[ECOMMERCE_CLOSED_LOOP_ROADMAP.md](ECOMMERCE_CLOSED_LOOP_ROADMAP.md)。

## 1. 目标

在没有真实 API 写权限、千牛账号只能查看的条件下，把已有平台导出安全接入现有商品、
订单、库存、指标、营销和财务领域服务，形成一套可重复导入、可追溯、可核对的只读
Demo 事实底座。

M7-R 不负责得出销售、流量、补货或利润结论；它负责回答三个问题：

1. 这项数据来自哪里、覆盖什么店铺和时间、是否仍然新鲜？
2. 平台商品、SKU、商家编码和内部料号能否唯一对应？
3. 后续 M8-R～M10-R 所需字段哪些是真实、人工配置、演示参数或缺失？

对应功能：F-323，并推进 F-208 的报表/文件只读兜底路线。

## 2. 范围与边界

### 范围内

- 订单、商品、库存、订单导出的履约/物流快照、经营指标、推广、退款和收入等平台导出的
  CSV/XLSX 适配。
- 报表级 manifest、字段白名单、schema fingerprint、内容摘要、来源时间和重放结果。
- 平台商品/SKU/商家编码/内部料号映射、歧义隔离和人工裁决入口。
- 真实数据、人工配置、演示参数、缺失数据四态证据契约，以及实际来源类型契约。
- 数据准备度、缺失项、时间覆盖、映射覆盖和隔离记录的只读工作台。
- 通过现有公开领域服务写入规范化事实；不直接绕过 service 插表。

### 范围外

- 操作千牛页面、复用浏览器 Cookie、抓取未授权接口或模拟人工点击。
- 客服消息实时接收、平台商品写回、采购、付款、退款、改价或库存调整。
- 将原始顾客姓名、手机号、地址或完整聊天内容放入 Git、日志、模型或 Eval。
- 为缺失的采购成本、订购单、运输周期和二次销售整备成本编造真实值。

## 3. 数据接入优先级

| 层级 | 数据域 | M7-R 处理方式 |
|---|---|---|
| 必需事实 | 商品/SKU、订单与每日销量、库存、订单导出的履约/物流快照、退款/售后状态 | 没有就不能进入对应后续主链，必须显示缺失或隔离原因 |
| 增强信号 | 曝光、点击、转化、广告、推广归因、竞品 | 有则接入并标质量；没有不阻断基础订单预测 |
| 财务输入 | 收入、平台费用、广告费用、退款费用等 | 只形成费用事实与缺口，不在本里程碑宣称净利润 |
| 人工经营参数 | 料号、MOQ、供应商承诺交期、复核周期等 | 支持版本化人工配置；当前拿不到时保持缺失 |
| Demo 假设 | 采购成本、运输周期、整备成本、订购单样例 | 只能以“演示参数”进入专用 Demo 数据集，不得污染真实事实 |

## 4. 统一导入契约

每次导入必须产生稳定 manifest，至少包含：

```text
import_id
tenant_id / store_id
source_kind                 actual | manual | demo
source_system / report_type
report_period
exported_at / imported_at
schema_fingerprint
content_digest
mapping_version
accepted_rows / quarantined_rows / rejected_rows
data_as_of
references
```

字段准备度另行记录：

```text
evidence_state              actual | manual | demo | missing
field_key / scope / reason
data_as_of / source_reference optional
```

要求：

- 相同内容、相同来源和相同版本重放幂等；同版本不同内容冲突。
- 字段名、枚举、证据四态、来源类型和报表适配器注册表各自只有一个权威定义。
- 未在白名单的列不进入规范化载荷；敏感列在落普通日志或模型前移除。
- 逐行错误进入隔离记录，不能用整表成功掩盖静默丢行。
- 真实数据与演示数据在存储、查询、页面和评测中都可区分，默认经营视图不混入 Demo。
- `missing` 只表示字段没有可靠证据，不创建 import manifest，也不得伪造成 `source_kind`。
- 千牛只读人工核对可以作为说明附件，但不能替代 manifest、来源版本或 Connector 证据。

## 5. 商品身份与对账

商品身份链统一为：

```text
店铺商品链接 / item_id
        └─> 平台 SKU
                └─> 商家编码
                        └─> 内部料号
```

自动匹配必须输出使用的稳定键和置信证据。零候选或多候选进入人工裁决队列，禁止按标题
相似度静默绑定。人工裁决需版本化、可撤销，并让后续订单、库存、预测和订购单引用同一
canonical mapping。

### WP1 导入契约、隐私白名单与证据四态

交付：

- 单一 import manifest、`actual/manual/demo` 来源类型、四态字段证据、数据质量和隔离错误契约。
- 各报表允许字段/敏感字段策略，以及导入前脱敏与普通日志投影。
- 原始文件受控存储边界、内容摘要和重放/冲突语义。

完成条件（由 WP5 独立复验）：

- 含顾客姓名、手机号、地址和非白名单列的样本不会进入规范化载荷、模型或普通日志。
- 相同文件重放幂等；同来源版本不同内容被拒绝。
- `missing` 不会生成导入记录或在数值投影中变成 0，`demo` 不会在默认 operational 查询中出现。
- 反证：移除敏感字段拦截或来源隔离后，对应测试失败。

依赖：D-014、D-033、D-035；不依赖新平台权限。

### WP2 平台报表适配器与规范化写入

交付：

- 商品、库存、订单、履约/物流快照、经营指标、推广、退款和收入报表适配器。
- 表头别名、日期/金额/枚举规范化、逐行拒绝和报表粒度校验。
- 通过现有 catalog/orders/inventory/metrics/marketing/finance 公开服务写入的编排层。

完成条件（由 WP5 独立复验）：

- 每个已登记适配器至少有正常、字段缺失、非法类型、重复、乱序和跨店反例。
- 日、月、订单行等不同粒度不混算；金额单位和时区显式记录。
- 一个适配器失败不让其他已成功域回滚成“全部未导入”，同时报告部分成功事实。
- 不直接写领域底表，不新增第二套订单、库存或财务真相。

依赖：WP1、F-303、F-305～F-309。

### WP3 商品/SKU/商家编码/料号映射与对账

交付：

- canonical 商品身份、映射候选、人工裁决、撤销和版本化查询。
- 订单行与库存 SKU 的对账报告，输出 matched/ambiguous/unmapped/rejected 明细。
- 后续订购单可使用的稳定内部料号引用。

完成条件（由 WP5 独立复验）：

- 同一料号在不同店铺或租户下不会串联；同租户多店也必须带 store scope。
- 标题相似但 SKU/商家编码冲突时进入歧义，不自动绑定。
- 人工裁决后重放稳定；撤销后新计算不再消费旧映射，历史证据仍可读。
- 所有输入行都有可解释终态，无静默丢弃。

依赖：WP1、WP2 的商品/订单/库存规范化输出。

### WP4 数据准备度 API、只读工作台与端到端 Demo

交付：

- 按店铺、数据域展示来源、覆盖区间、水位、新鲜度、质量、映射和缺失项的只读 API。
- 导入批次、隔离记录、人工映射和字段证据四态的后台页面。
- 一键装载脱敏 Demo 数据集并运行只读核验的场景证据。

完成条件（由 WP5 独立复验）：

- 页面一眼区分真实、人工、演示和缺失；每个数值可追到 import manifest。
- 只打开页面不会触发导入、重建、模型调用或任何平台写动作。
- Demo 重放不增加重复事实；默认 operational 范围不显示 demo/simulation。
- 页面和 API 对缺失采购成本、订购单、运输周期、整备成本给出相同缺口状态。
- 浏览器桌面与窄屏可读，console 无新增错误。

依赖：WP1～WP3、F-310。

### WP5 M7-R 独立验收、反例与里程碑签署

交付：

- 独立审阅 WP1～WP4 的完整差异、数据契约、迁移/兼容边界和交付清单。
- 使用未参与开发的样本复跑导入、映射、准备度 API、页面和端到端 Demo。
- 敏感字段、跨店隔离、缺失转零、Demo 混入 operational、幂等/冲突等反例或 mutation。
- 独立验收报告、失败清单、复验记录和明确的通过/不通过结论。

验收纪律：

- 缪海南可以编写独立测试、探针和验收报告，但不得替谢良璇修改 WP1～WP4 的实现。
- 发现问题必须退回谢良璇修复；修复后由缪海南重新检查差异并从干净状态复跑。
- 若缪海南参与 M7-R 功能实现，则必须更换一名未参与 M7-R 开发的人重新完整验收。

通过条件：

- WP1～WP4 的全部完成条件、完整回归、浏览器、隐私和写屏障门禁均有独立证据。
- 至少一项关键反例或 mutation 在破坏边界时失败、还原后恢复通过。
- 验收报告只签署已验证范围，不把 Demo、真实平台接入或生产放行冒充完成。

依赖：WP1～WP4 全部交付；不得与其功能开发并行代写。

## 7. M7-R Definition of Done

M7-R 进入本机候选前必须同时满足：

- 已登记报表均能生成可追溯 manifest，逐行错误无静默丢失。
- 敏感字段不进入 Git、模型、普通日志和 Eval；脱敏边界有有效反证。
- 商品/SKU/商家编码/料号映射可解释、可裁决、可撤销且跨店隔离。
- 后续里程碑能通过公开服务读取同一份事实、来源类型和字段证据四态，不另建旁路。
- 只读 Demo 可重放，千牛账号、浏览器登录态和页面操作不成为运行依赖。
- WP1～WP4 由谢良璇完整交付并自测，WP5 由缪海南独立复验签署；完整回归与台账校验通过。
