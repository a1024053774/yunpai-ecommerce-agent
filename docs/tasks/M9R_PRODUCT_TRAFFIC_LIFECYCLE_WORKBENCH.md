### 背景和模块说明

落实刘经理对 M5-R 的要求：解决平台内链接和 SKU 的经营问题，让商品更符合平台展示
和流量分配所需要的可观测条件，以获得更多曝光机会。系统不猜平台内部权重，而是复用
M5-R 的版本化 revision、指标、受控实验和黑盒分析证据，回答：

- 哪些商品当前需要保持、观察、上新、诊断或进入受控实验？
- 曝光、点击、转化、库存、价格、广告和竞品之间有哪些可复核变化？
- 选品、定价、活动、补货和清仓下一步应准备什么，哪些条件仍缺失？

对应功能：F-325。

### 模块具体需求

#### 具体需求一：产品硬边界

- 存量商品默认**不改标题、不换主图**。标题错误、关键词陈旧，或曝光/点击表现差且
  数据质量满足时，系统才可提出人工审核建议；一般优先建议上新或受控实验。
- 不自动发布商品、改价、换图、报名活动、调整广告或下架清仓。
- 不宣称“平台标题权重”“主图权重”或逆向得到平台算法。
- 商品生命周期输出是带证据的建议，不是无需人工确认的事实状态。
- 精确价格动作必须考虑成本和利润准备度；M10-R 未提供完整成本时，M9-R 不给
  “一定提价 2 元”一类正式结论。

#### 具体需求二：经营读模型

每个 `store + item + SKU` 建立统一经营读模型，但每项指标必须保留自己的真实粒度，不能
因为读模型以 SKU 展示就把店铺总量复制到 SKU。当前样例可提供 SKU 级商品、交易和库存，
流量/广告主要是店铺日级或报表聚合，且没有 listing revision 生效时窗。

因此 V1 分成两条严格隔离的证据路径：

- **真实导出路径**：先展示 SKU 交易/库存、店铺级流量背景和逐字段准备度；没有 SKU 级
  曝光/点击时，SKU 流量漏斗与 M5-R 实验状态必须为 `missing/blocked`。
- **模拟 Demo 路径**：使用显式 `demo` 的 SKU 流量、不可变 revision 和实验窗口，完整跑通
  M5-R 诊断、实验与生命周期建议；结果不得进入默认 operational 查询或冒充真实店铺结论。

读模型覆盖以下证据域：

| 证据域 | 主要字段 | 来源 |
|---|---|---|
| 商品 | 标题、主图版本、价格、属性、上架状态、商家编码/料号 | M7-R / F-305 |
| 流量 | 曝光、访客、点击、CTR、加购、转化、来源结构、数据时间、原始粒度 | M7-R / M5-R；当前真实样例仅店铺/聚合级，SKU 级用 Demo 或保持缺失 |
| 交易 | 下单、支付、退款、净销量可用性、销售额 | M7-R / F-306/F-307 |
| 库存 | 可售、在途、覆盖天数、缺货/积压风险 | F-303 / M10-R |
| 广告/活动 | 花费、归因成交、ROI 可用性、活动窗口 | F-308 / M7-R |
| 竞品 | 已批准同款、价格、销售区间和变化 | F-304；没有可靠来源时标 missing |
| 实验 | revision、实际窗口、uplift、区间、质量、反证、新鲜度 | F-312～F-316；当前先以隔离 Demo 跑通，真实模式等待 revision/窗口证据 |

“净销量”“广告 ROI”“利润安全价格”等不可用时必须保留不可用状态，不以支付件数、
GMV 或缺失成本替代。

#### 具体需求三：生命周期建议链

V1 提供以下建议类型，不建立自动执行路径：

```text
选品候选
  └─> 上新准备
        └─> 曝光/点击诊断
              └─> 受控实验或保持观察
                    └─> 定价/活动候选
                          └─> 补货联动
                                └─> 清仓预警或退役建议
```

代码计算时间窗、指标、质量、库存和权限等事实；模型根据用户目标和固化事实决定语义
下一步、解释证据与反证。允许动作集合与写屏障由代码控制，模型不能把建议变成平台动作。

### 模块验收标准

- 商品/SKU 经营读模型覆盖流量、交易、库存、广告、竞品和实验的粒度及可用/缺失状态；
  当前真实数据不满足 SKU 流量条件时不得形成 SKU 流量结论。
- 隔离模拟数据能跑通 revision/实验/诊断全链，但不进入默认经营视图，不冒充真实店铺证据。
- M5-R 统计事实与 AI 解释边界保持，不能输出平台内部权重或无证据因果结论。
- 生命周期建议覆盖选品到清仓，并以人工确认、可追溯和无平台写动作收口。
- 存量标题/主图默认不改的产品原则有代码边界、页面说明和反证测试。
- WP1～WP4 由胡磊完整交付并自测，WP5 由闫睿涵独立复验签署；独立 Eval、浏览器、
  租户/店铺隔离和完整回归通过。

### 模块交接内容

- `store + item + SKU` 经营读模型、字段原始粒度、来源、新鲜度、证据状态与数据准备度。
- M5-R revision/experiment/analysis/freshness/provenance 证据桥接和结构化流量诊断。
- 版本化商品生命周期建议、人工审核状态机、陈旧标记和后续观察记录。
- 商品经营工作台、真实/演示双路径、结构化机制 Eval、反例和浏览器证据。
- 数据模型/查询/API 说明、测试与反证证据、Demo 隔离说明和 WP5 独立验收报告。

### WP1 Listing/SKU 经营读模型与数据准备度

**任务名称**

Listing/SKU 经营读模型与数据准备度

**任务内容**

建立按租户、店铺、商品、SKU 和 revision 隔离的经营聚合读模型，显式保留字段原始粒度、
料号、来源、新鲜度和缺失状态，为流量诊断与商品建议提供可追溯事实。

**具体需求**

- 建立 store + item + SKU 聚合读模型，并保留字段原始粒度、料号引用、来源和 data_as_of。
- 粒度允许时形成曝光→点击→加购→支付→退款漏斗；粒度不足时展示可用事实与明确缺口。
- 对跨粒度、跨店、跨 SKU、跨 revision 和缺失状态执行确定性检查。
- 复用现有领域事实表和公开服务，不复制第二套商品、交易、库存或流量真相。

**验收标准**

- 同一 item 多 SKU、同一 SKU 多 revision 和同租户多店不会串数。
- 日/月、店铺/商品、支付/退款等不同粒度不能被静默相加。
- 店铺级曝光、点击、广告或转化不能广播、均摊或推导成 SKU 指标。
- 缺广告、竞品或退款明细时仍可显示基础流量事实，但明确阻断依赖它们的结论。
- 读模型每个值可回溯到权威服务、import manifest 和 data_as_of。

**交接内容**

- 经营读模型 schema/API、范围键、字段原始粒度和聚合规则。
- 漏斗可用性、数据准备度、来源、新鲜度和缺失阻断语义。
- 跨店、跨 SKU、跨 revision、混粒度和店铺指标拆分反例证据。
- 固定消费的 M7-R 输出版本及供 WP2～WP4 使用的查询示例。

### WP2 M5-R 证据桥接与流量诊断

**任务名称**

M5-R 证据桥接与流量诊断

**任务内容**

把 M9-R 商品经营读模型与 M5-R 的 revision、experiment、analysis、freshness 和 provenance
证据接成统一只读查询，基于固化数值和 Gate 生成可反驳的流量诊断与实验建议。

**具体需求**

- 统一查询商品经营事实与 M5-R revision/experiment/analysis/freshness/provenance 证据。
- 物理区分真实与 Demo 查询范围，并让 demo 标签贯穿 API、页面和报告。
- 输出曝光不足、点击不足、转化不足、缺货污染、广告/价格变更污染和证据不足诊断。
- 模型只解释固化证据、反证和下一轮单变量实验建议，不修改数值或确定性 Gate。

**验收标准**

- 只有满足 A/A、样本、实际窗口、控制变量和 freshness Gate 的实验才给强方向结论。
- 缺货、广告或价格变化不会被错误归因于标题/主图。
- 模型越权修改 effect、区间、样本量、Gate 或声称平台权重时整份解释被拒绝。
- 没有合格实验时返回观察/补数/实验建议，不编造 uplift。
- 真实样例缺 SKU 流量或 revision 窗口时返回 blocked；显式 Demo 可演示但全链保留 demo 标签。
- 任何诊断均不产生 listing、图片、广告或活动写动作。

**交接内容**

- M9-R/M5-R 统一查询接口、证据引用和真实/Demo 范围说明。
- 结构化诊断类型、确定性 Gate、污染原因和 blocked 语义。
- 模型解释输入/输出契约、越权拒绝和单变量实验建议模板。
- A/A、样本、窗口、污染、无证据、demo 隔离和写屏障测试证据。

### WP3 商品生命周期建议、人工确认与跟踪

**任务名称**

商品生命周期建议、人工确认与跟踪

**任务内容**

基于固化经营事实和流量诊断生成版本化商品生命周期建议，通过人工审核状态机跟踪建议、
观察和关闭结果；批准只代表内部确认，不触发任何平台动作。

**具体需求**

- 记录建议类型、目标对象、事实快照、假设、收益/风险、缺失项、来源和版本。
- 实现 draft → awaiting_review → approved/rejected → observed → closed 的建议跟踪状态机。
- 提供选品、上新、保持、诊断、实验、定价候选、活动候选、补货联动和清仓预警模板。
- 语义建议由模型产生，代码只校验允许类型、必需证据、状态、幂等和写屏障。

**验收标准**

- 建议默认 draft，只有人工可批准/拒绝；批准仍不触发平台动作。
- 存量标题/主图默认 keep/observe；满足任务书条件时才显示人工复核优化，并保留优先上新/实验替代方案。
- 缺成本时不能输出正式利润安全价格；缺竞品时不能假装有行业对标。
- 同一证据重放不重复创建建议；事实更新后旧建议标 stale，不原地改写历史。
- 语义建议由模型产生，确定性代码不以标签或关键词替代模型判断。

**交接内容**

### WP4 商品经营工作台与机制 Eval 能力

**任务名称**

商品经营工作台与机制 Eval 能力

**任务内容**

建设可从商品/SKU 下钻到 revision、时间窗、来源、实验和建议依据的只读经营工作台，并用
数值与结构化机制 Eval 验证真实方向、拒绝污染结论和人工审核边界。

**具体需求**

- 实现商品列表、漏斗、流量诊断、实验、来源、建议、人工审核和后续观察页面。
- 冻结选品、上新、存量保持、受控优化、污染、缺数据和清仓风险场景。
- 同时覆盖真实粒度不足与显式模拟实验可运行两条路径，并保留来源标签。
- 使用数值与结构化机制 Eval，不以文案关键词或表面措辞作为裁判。

**验收标准**

- 页面能从商品/SKU 下钻到 revision、时间窗、指标、来源和建议依据。

- 查看页面不自动分析、创建实验、创建建议或修改商品；运行操作必须显式点击并审计。
- Eval 同时证明能发现真实方向和拒绝无效/污染方向，ground truth 不进入生产输入。
- 浏览器桌面与窄屏可读，console 无新增错误。

**交接内容**

- 商品经营工作台页面、下钻路径、显式运行/审核操作和审计说明。
