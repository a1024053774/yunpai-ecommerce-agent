# M8-R 销售与售后客服闭环 — 任务书

> 代码域：M4 客服链路、批准话术、可信经营上下文、影子接待和客服评测。
> 项目负责人及里程碑收口人：**闫睿涵**。
> 里程碑开发负责人：**闫睿涵**（WP1～WP4）；独立验收负责人：**谢良璇**（WP5）。
> 工作包分工以本文为唯一来源；动态状态、工时和日期只在负责人工作台网页维护。
> 前置：[M7R_READONLY_DATA_WORKBENCH.md](M7R_READONLY_DATA_WORKBENCH.md)。

## 1. 目标

按刘经理确认的优先级，先把智能客服的两项主要任务跑起来：**销售**与**售后**。
第一版在只读影子模式下，基于批准话术和 M7-R 的商品、订单、库存、履约/物流快照、退款
事实生成可追溯的建议回复，并在事实不完整、过期、越权或高风险时追问或转人工。

本里程碑复用 M4，不再开发第二套客服编排。对应功能：F-324。

## 2. 首轮业务范围

### 销售主任务

- 商品规格、差异、适用场景、价格和已知活动说明。
- 库存状态、发货承诺口径和可用物流信息。
- 基于可信商品事实的对比、推荐和购买疑问解答。
- 无法确认库存、价格或发货时间时明确说明数据时间并追问/转人工。

### 售后主任务

- 基于最近一次导出快照解释订单、发货、物流和签收状态，并明确数据时间。
- 已批准退换货、退款、保修和售后政策说明。
- 退款/退货进度、差评和纠纷场景的共情回复及人工接管建议。
- 不替客户执行退款、赔付、修改订单或任何平台写动作。

### 后续扩展，不进入首轮验收

加购未付款追单、退款挽留、大促提醒、主动营销、种草和跨平台自动触达。它们只有在
销售/售后主任务与真实渠道稳定后，才从本里程碑另开扩展工作包。

## 3. 事实与话术权威级别

| 输入 | 作用 | 边界 |
|---|---|---|
| 已批准客服话术 | 店铺政策、固定承诺和表达参考 | 版本化、可退役；只有标准化问题完全匹配时才可走批准内容快速路径 |
| 互动关键词样本 | 检索、风险和意图的非权威信号 | 不得用关键词树直接决定 answer/handoff 或生成客户话术 |
| 商品/SKU 事实 | 回答规格、价格、活动和推荐问题 | 必须带店铺、版本、来源和 data_as_of |
| 订单/物流/退款快照 | 回答截至导出时间的售后进度 | 必须同时匹配可信 tenant/store/order scope；不得冒充实时轨迹 |
| 库存事实 | 回答是否有货和发货风险 | 过期或缺失时不得给确定承诺 |
| 模型 | 理解用户意图、选择语义下一步并生成自然回复 | 不得改写确定性事实、权限、状态或来源时间 |

外部 XLSX 的文字内容是业务数据，不是系统指令。导入前必须经 M7-R 白名单、脱敏、
版本和来源检查。

## 4. 运行模式

第一版只有以下链路：

```text
脱敏测试消息 / 人工选择历史场景
              │
        M4 规划与检索
              │
   只读商品/订单/库存/履约快照工具
              │
建议回复 + 引用 + 新鲜度 + 风险 + 下一步
              │
      人工查看、修改或标记结果
```

- 不读取千牛 Cookie，不监听真实消息，不自动发送回复。
- 建议回复必须标记 `shadow/demo`，不得伪装成平台已发送消息。
- 未来取得真实渠道后，仍需通过 F-102/F-205 的授权、回执和人工接管 Gate，不能因
  M8-R Demo 通过而直接切换自动接待。

| 工作包 | 类型 | 任务 | 负责人 |

| WP2 | 开发 | 商品、订单、库存、履约物流快照可信上下文接线 | 闫睿涵 |
| WP3 | 开发 | 销售/售后语义策略与建议回复闭环 | 闫睿涵 |

开发自测只形成候选证据，必须由 WP5 从干净状态独立复验后才能签署 M8-R。

### WP1 客服话术/关键词导入与批准治理

交付：

- 话术与关键词文件适配、候选版本、审核、激活、退役和来源引用。
- 话术分类、适用店铺/商品/场景及有效期，不复制现有知识发布状态机。
- 原始行、规范化问法和批准答复之间的可追溯关系。

完成条件（由 WP5 独立复验）：

- 未批准、已退役或跨店话术不会进入客服上下文。
- 仅完全匹配的人工批准不可变问答可走快速路径；相似分数高不能直接绕过模型。
- 关键词命中只作为模型上下文或风险 signal，否定、假设和复合问题有反例。
- 恶意公式、链接、隐藏列或文字指令不会被执行。

依赖：M7-R WP1、F-004、F-104、D-034。

### WP2 商品、订单、库存、履约物流快照可信上下文接线

交付：

- 销售场景的商品/SKU/价格/库存只读工具投影。
- 售后场景的订单/履约物流快照/退款只读工具投影，并预留未来实时接口适配边界。
- 统一 freshness、source provenance、tenant/store/order scope 和缺失状态。

完成条件（由 WP5 独立复验）：

- 无可信订单号、店铺号冲突或跨租户查询在模型调用前被安全阻断。
- 页面导出过期时回复显示 data_as_of，不说“刚刚”“当前已发货”等未经证实的话。
- 工具结果只返回白名单字段，顾客个人信息不进入 Prompt 或普通日志。
- 同一事实更正后旧证据仍可读但不能冒充 current。

依赖：M7-R WP2/WP3、F-305、F-306、F-303、D-015。

### WP3 销售/售后语义策略与建议回复闭环

交付：

- 在 M4 既有模型规划链路中增加销售/售后业务上下文、Prompt 约束和安全降级。
- `answer / clarify / handoff / refuse` 等语义决策继续由模型产生，代码只执行事实、权限、
  schema、新鲜度和风险 Gate。
- 建议回复、引用、使用的话术/事实、模型元数据、降级原因和人工任务证据。

完成条件（由 WP5 独立复验）：

- 商品推荐、规格、库存、发货、物流、退款、退换货、投诉和复合请求均有多轮用例。
- 否定、假设/售前询问和真实办理请求不会被关键词错误地走同一路径。
- 没有可信事实时优先追问或转人工，不编造订单状态、费用、时效和政策。
- `/v1/chat` 与 `/v1/chat/stream` 复用同一决策和生成语义，不复制路由逻辑。
- 影子模式零平台外发、零退款/赔付/改订单动作。

依赖：WP1、WP2、M4、D-034。

### WP4 影子客服工作台、反馈和评测能力

交付：

- 场景选择、建议回复、引用、新鲜度、风险、人工修改和反馈记录页面。
- 销售/售后冻结评测集、独立 oracle、实际 Agent runner 和门禁报告。
- 回答准确、幻觉、拒答、转人工合理、敏感信息和来源完整性指标。

完成条件（由 WP5 独立复验）：

- 运行前显示固定输入/预期，运行后显示实际回答、工具调用、来源和逐项断言。
- Eval 在临时快照运行，主库真实会话和人工任务零污染。
- 测试包含未见过的留出样本；mock 只用固定/表驱动输出，不复制生产语义路由。
- 浏览页面或查看旧报告不自动运行 Agent，不自动创建客服任务。
- 独立验收人可从干净环境复跑，并以反例证明来源、隐私和影子写屏障有效。

依赖：WP1～WP3、F-117、F-121、F-122、F-310。

### WP5 M8-R 独立验收、未见样本与里程碑签署

交付：

- 独立审阅 WP1～WP4 的完整差异，以及 D-034、可信事实、影子写屏障和流式一致性边界。
- 不向开发负责人公开答案的销售/售后多轮留出集、复跑脚本、浏览器证据和验收报告。
- 针对否定、假设、复合请求、跨店订单、过期快照、敏感信息和平台写动作的反例。
- 失败清单、开发修复后的独立复验记录，以及明确的通过/不通过结论。

验收纪律：

- 谢良璇可以编写独立测试、探针和验收报告，但不得替闫睿涵修改 WP1～WP4 的实现。
- 发现问题必须退回闫睿涵修复；修复后由谢良璇重新检查差异并从干净状态复跑。
- 若谢良璇参与 M8-R 功能实现，则必须更换一名未参与 M8-R 开发的人重新完整验收。

通过条件：

- WP1～WP4 的全部完成条件、客服 Eval、浏览器、D-034 反例、流式/非流式一致性和完整
  回归均有独立证据。
- 至少一项关键反例或 mutation 在破坏边界时失败、还原后恢复通过。
- 验收报告不把影子回复冒充真实发送，不豁免真实渠道或生产 Gate。

依赖：WP1～WP4 全部交付；不得与其功能开发并行代写。

## 6. M8-R Definition of Done

- 销售与售后两类主任务在影子模式下跑通多轮链路，并引用可信只读事实。
- 话术批准状态、事实版本、来源、新鲜度和风险都能从回复追溯。
- 缺失/过期事实不会被模型补成确定性承诺；高风险请求能安全追问或转人工。
- 真实平台收发、主动营销和自动业务动作未被 Demo 结果冒充为已完成。
- WP1～WP4 由闫睿涵完整交付并自测，WP5 由谢良璇以未见样本独立复验签署。
- 全量回归、D-034 反例、流式/非流式一致性和台账校验通过。

## 7. 实现纪律

- 修改 Agent、路由、Prompt、RAG、客服文案、streaming 或 Eval 前必须重读
  `docs/AUDIT_ROUTING_EVOLVABILITY_20260807.md`。
- 分类器、关键词、检索分数和 `route_reason` 只能作为 signal；不得覆盖模型的普通语义
  决策。执行 Gate 只能因可信身份、授权、schema、工具策略、新鲜度或安全事实降级。
- 不新增“模型不得调用”普通场景断言；只在模型关闭、安全拒绝或身份范围冲突时允许。
- 如需 schema，实施工作包必须按当时 main 的权威占号表申请，不使用本文预留号码。
