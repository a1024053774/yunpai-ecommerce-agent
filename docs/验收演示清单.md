# M3 知识库 · 验收演示清单（负责人 10 分钟走完）

> 目的：让验收方按顺序操作即可完整看到 M3 知识库的全部能力，无需摸索。
> 适用：本地一体机部署（Windows）。全部操作在浏览器完成。

## 〇、准备（2 分钟）

1. **启动服务**（先加载 .env）：
   ```bash
   cd <项目根目录>
   export $(grep -v '^#' .env | grep -v '^$' | xargs)
   .venv/Scripts/python.exe -c "from ecommerce_agent.api import create_app; import uvicorn; uvicorn.run(create_app(), host='127.0.0.1', port=8000)"
   ```
2. **可选：启动 Neo4j**（图谱可视化用；不启动不影响列表/详情/搜索）：
   ```bash
   docker compose up -d          # 方式 A
   # 或本机启动 neo4j.bat console  # 方式 B
   ```
3. **浏览器打开控制台**：`http://127.0.0.1:8000/admin`，登录（管理员 ID 和 .env 的 `ADMIN_API_KEY`）。

> ⚠️ 真实模型：若要演示"客服真实回答"，需在 .env 配 `MODEL_ENABLED=true` + `MODEL_API_KEY`（见文档"演示环境配置"）。否则客服走 mock（规则回复）。

## 〇·补、演示环境配置（产品-1：验收演示用真实模型）

```bash
# .env 中配置（验收演示前）：
MODEL_ENABLED=true          # 开启真实模型
MODEL_MOCK_MODE=false       # 关闭 mock

curl http://127.0.0.1:8000/health | python -m json.tool
```

## 一、知识库总览（1 分钟）

1. 左侧导航 → **「知识库」**（第 17 个模块）
2. 看 **KPI 概览**：词条总数（约 370+）、运行时知识（可编辑）、资产层词条（只读）
3. 看 **数据来源**：运行时知识（可编辑）vs 资产层（02_clean 只读）

## 二、词条浏览 + 分类导航（2 分钟）

1. **类型导航**：点「行业规则」→ 列表只剩 rule 类；点「FAQ」→ 只剩 faq 类
2. **分页**：点「下一页」→ 翻页正常（每页 50 条）
3. **词条详情**：点任意一行 → 看「当前结论 / 属性 / 演化历史时间线」

## 三、知识搜索（1 分钟）

1. 顶部搜索框输入 **「保修」** → 点搜索
2. 应命中运行时知识表的保修相关词条（**不依赖 Neo4j**，编辑内容即时可搜）

## 四、编辑闭环（2 分钟，核心验收）

1. 搜索或导航到一条 **FAQ** 词条（如"保修多久"）
2. 点详情 → **「保存修改」** → 输入新答案
3. 返回 **candidate** 状态（说明"走审批流：draft→evaluate→approve"）
4. 到「知识与 SOP」模块（/v1/admin/knowledge）→ 找到该条 → evaluate → approve
5. 回到「知识库」→ 刷新 → 词条详情显示**新结论**，时间线追加 revised 记录

> 设计意图：编辑走治理审批流（可回滚、可溯源），不是"保存即改"——这是 ToB 治理门禁。

## 五、知识图谱（2 分钟，需 Neo4j）

1. 点「在新标签打开图谱」→ 图谱视图加载（需已登录控制台，鉴权已保护）
2. D3 力导向图可缩放/拖拽，点击节点看详情
3. 若 Neo4j 未启动：图谱按钮提示"图谱服务暂不可用"，**列表/详情/搜索不受影响**

## 六、图谱检索 API（1 分钟，需 Neo4j）

```bash
# 多跳推理：空气炸锅 → 品类 ← 政策（返回 3 条政策）
curl -X POST http://127.0.0.1:8000/v1/graph/multi-hop \
  -H "Content-Type: application/json" -H "X-Admin-Id: <admin>" -H "X-Admin-Key: <key>" \
  -d '{"start_id":"QC-AF5-WHITE","rel_types":["BELONGS_TO","APPLIES_TO-"]}'
# 图谱统计
curl http://127.0.0.1:8000/v1/graph/stats -H "X-Admin-Id: <admin>" -H "X-Admin-Key: <key>"
```

## 六·补、店铺长期记忆（1 分钟，A1/A2/A5：P1-2 接线后演示）

1. 「知识库」页底部「**店铺长期记忆**」面板
2. 输入店铺 ID（如 `qinchuan`）→ 记忆内容（如"本店保修政策已升级为 36 个月"）→ 类别选「决策记录」→ **记录记忆**
3. 同一店铺 → **召回** → 看到刚记录的记忆；换店铺 ID 召回 → 空（**店铺隔离**生效）
4. 删除测试记忆（演示 forget）
5. 演示后客服回答中记忆会作为补充证据并入检索（`memory://` 来源，显式召回）

## 六·补2、知识库自动维护（1 分钟，A3：梦循环接入服务生命周期）

1. 服务启动后日志出现 `knowledge-worker` 首次梦循环报告（导入 + 一致性 + 合并）
2. 健康检查含知识库 worker 状态：
   ```bash
   curl http://127.0.0.1:8000/health | python -m json.tool
   # → "knowledge_worker": {"enabled": true, "running": true, ...}
   ```
3. 每日自动跑：梦循环（合并结论落库 `kg-consolidated-*`）+ 35 题检索评测（通过率 < 0.9 告警）

## 八、已知边界（负责人须知）

- **商品为虚拟种子**：8 SPU / 12 SKU（晴川空气炸锅等），非真实电商数据；架构支持扩展（02_clean 加数据即生效）
- **关系准确率待人工标注**：60 条抽样模板已生成（`sampling_plan.csv`），标注指南见 `sampling_review_instructions.md`——这是合同要求的人工抽检，不再是"自动 100%"
- **图谱为静态快照**：编辑知识后需重跑 `export_graph.py` 才同步到图谱；Wiki 列表/详情/搜索即时生效
- **Neo4j 密码**：本地开发 `neo4j/${NEO4J_PASSWORD:-change-me}`（docker-compose 默认），生产改 `NEO4J_AUTH`
