# PR #25 P1 承诺边界人工复验指南

测试人：谢良璇。

## 为什么单独复验

负责人在旧 head `da1e1c2` 上发现：只读事实查询成功后，系统可能放行未经证实的发货时间
承诺，或把退款进度查询说成“已经替客户办理退款”。本复验只检查这次 P1 修复，不覆盖或
改写此前 WP3 八步人工验收结果。

## 开始操作

打开新的 PowerShell，逐行执行：

```powershell
Set-Location "F:\CodexProjects\yunpai-ecommerce-agent-m8r-dev"

& ".\docs\works\18-feature-m8r-customer-service-loop\PR25_P1_承诺边界人工复验.ps1"
```

不要加 `-AutoConfirm`。该参数只用于开发者验证脚本能否运行，不能形成谢良璇的人工结论。

## 六步观察重点

| 步骤 | 应看到什么 |
|---|---|
| 1. 发货承诺 | “明天一定发货”在流式和非流式都被拦截；48 小时、明天安排、只答“明天”和连接词掩盖等变体同样被拦截；一条已验证事实不能授权另一句未验证承诺，“预计明天送达”也不能被升级成“明天送达”；同等谨慎的事实复述、真实已验证事实和“需要人工核对”的安全文案正常放行 |
| 2. 退款与订单动作声称 | “已经帮您办理退款了”及换货、补发、改地址/手机号/抬头、拦截、催发、备注、优惠券、删单、确认收货、延期等自然口语完成声称均被拦截；“查询退款状态”不会被误判成执行退款，纯退款/订单状态说明不被误伤 |
| 3. 全部出口 | 危险文案放在澄清、转人工或拒绝节点中仍会改写并转人工；正常“转人工”保留 `customer_requested_human` 和“请勿发送密码”安全提醒 |
| 4. 状态一致性 | 已发货/运输中/审核中的正例可回答；订单取消、物流签收、退款审核通过三个独立反例分别返回对应 mismatch 并转人工；完全无事实以及拿销售事实回答订单状态/拿售后事实回答库存状态时也转人工 |
| 5. 库存与状态 | 价格、否定和模糊问法不授权精确库存；在途、华东仓和错误商品状态同样被拦截 |
| 6. 授权不扩散 | 修改地址回执、失败回执和只含 `refund` 字样的无关工具名都不能授权退款声称；退款及各类订单动作只有各自匹配且成功的写回执可放行；密码与站外支付话术始终禁止 |

每一步请亲自阅读输出。符合预期输入 `Y`，不符合输入 `N`。六步全部确认后，结果应满足：

- `confirmation_mode=human`
- `automatic_contract_checks=passed`
- 6/6 observations 的 `confirmed=true`
- `human_observations_passed=true`
- `final_status=human_accepted`
